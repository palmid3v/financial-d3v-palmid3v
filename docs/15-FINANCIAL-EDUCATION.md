# Financial Education

Financial-D3v is intentionally an educational financial application.

The objective is not simply to store financial records. The application should help the user understand what the records mean and build better financial habits over time.

## Educational pillars

### Financial literacy
Teach concepts through real context:
- income;
- expenses;
- cash flow;
- budgets;
- savings;
- emergency funds;
- debt;
- interest;
- assets;
- liabilities;
- net worth;
- financial goals.

### Learning by doing

Record expense → categorize it → see budget impact → review monthly pattern → learn what the category means → decide what to change.

### Contextual explanations

Explanations should appear where useful instead of requiring the user to read a financial textbook first.

### Reflection

The application should help the user review what changed, why it changed, whether it matched the plan, what can be learned and what action might be worth considering.

## Insight model

An insight should conceptually contain:
- title;
- metric/fact;
- calculation;
- interpretation;
- educational explanation;
- optional suggested action;
- source records or period.

This makes insights traceable.

## Educational boundaries

The application must not:
- invent financial facts;
- guarantee investment returns;
- present legal/tax rules without authoritative verification;
- pretend to know the user's future;
- manipulate the user through fear or shame.

When external financial/legal information is needed, the source and effective date should be recorded.

## Personal savings objective

Savings is a first-class product outcome.

The system should help the user define a goal, define a target amount, define a target date where useful, record contributions, measure progress, understand required pace, compare plan versus actual and reflect on obstacles.

The application should teach the mechanics behind the numbers so the user becomes less dependent on it over time.
